Each page was loaded in a same-origin iframe at **360, 390, 740 (360×740 landscape), 768, 844 (390×844 landscape), 1024 and 1440 px**, waiting until its loading spinners were gone, then comparing `scrollWidth` with `clientWidth`. **126/126 pass** (18 pages × 7 widths): `/login`, `/signup`, `/forbidden`, 404, `/apply/profile`, `/apply/salary-slip`, `/apply/loan`, `/apply/status`, `/apply/loans`, `/apply/loans/:id`, `/dashboard`, `/dashboard/sales`, `/dashboard/sanction`, `/dashboard/sanction/:id`, `/dashboard/disbursement`, `/dashboard/collection`, `/dashboard/collection/:id`, `/dashboard/staff`. No app code has changed since PR #13's audit (`git diff 1bc86bc HEAD -- frontend backend` is empty).
- **E2** At 390×844 as admin: the Sanction queue renders **cards** (`ul.lg:hidden` visible, `<table>` hidden). **Menu** sets `aria-expanded="true"`; the drawer links are Overview/Sales/Sanction/Disbursement/Collection/Staff, **44px** each; choosing Staff navigates to `/dashboard/staff` and **closes the drawer**. Tallest dialog (Add staff member) at **844×390 landscape**: top 16, bottom 374 (inside the 390px viewport), `overflow-y: auto` and it scrolls inside. Long-text wrapping was verified in the PR #13 audit with a 60-character name and 70-character email (`docs/UI.md` checklist); the code is unchanged since.
- **E3** Scan at 390px (iframe, production build) of `/apply/loan`, `/apply/profile`, `/dashboard`, `/dashboard/sanction`, `/dashboard/sanction/:id`, `/dashboard/collection/:id`, `/dashboard/staff`, `/login`, `/signup`: **no button/link/input under 44px** (inline links inside sentences are excluded, as WCAG 2.5.8 allows). Every text input, select and textarea computes to **16px** (no iOS focus zoom). Both loan sliders are **44px** tall (28px thumb, `.slider` in `globals.css`). Dragging the slider by touch/pointer was verified in the PR #13 audit (₹1,00,000 → ₹4,49,000 with the total updating); code unchanged.
- **E4** Fresh tab, local **production** build, 10 pages visited (`/login`, `/signup`, `/apply/status`, `/apply/loans`, `/apply/loans/:id`, `/dashboard`, `/dashboard/sales`, `/dashboard/sanction/:id`, `/dashboard/collection/:id`, `/dashboard/staff`): **"No console logs"**: no errors, warnings or hydration messages. Dev-mode hydration was checked in the PR #13 audit (none); the code is unchanged.
- **E6** Slow network, simulated by wrapping `window.fetch` with a 3-second delay on the payment POST, local production build. **Three** clicks on "Record payment" within one frame → **1 POST**. While pending the button was `disabled`, `aria-busy="true"` and showed the spinner; afterwards it re-enabled and the toast read "Payment recorded. Outstanding: ₹2,90,274.04". The same guard (`useSingleFlight`) covers Apply, Approve, Reject and Mark disbursed: the PR #13 audit showed 3 clicks on Apply → 1 POST. Slow GETs show the page spinner, and on 502/HTML responses the "Waking up the server" banner with retries (`api-client.ts`).
- **E5** With the local API stopped, `/dashboard/sales` shows "Waking up the server. This can take up to a minute on the free hosting plan…" plus the "Loading your account" spinner, never a blank page. The final "The server is starting up. Please try again in a moment." + **Try again** state (which recovers once the API returns) was verified in the PR #13 audit. Error boundaries exist (`app/error.tsx`, `app/global-error.tsx`, `app/not-found.tsx`, `app/(borrower)/apply/error.tsx`, `app/dashboard/error.tsx`). The root, `/apply` and `/dashboard` boundaries were verified in that audit with forced render errors: each showed "Something went wrong", Try again and "Go to my home page", inside the shell for the segment boundaries. The code is unchanged, and the audit forbids re-adding crash triggers now.
- **E7** Accessibility:
  - **Focus order** on `/login` (Tab ×6, production build): Skip to content → Email → Password → Log in → Create an account → back to Skip to content. The brand panel has no focus stops.
  - **Visible focus** on every element: inputs and the button show a 2px solid outline; links show the browser's auto focus ring.
  - **Labels:** every form control has a label (UI kit `TextField`/`SelectField` via `htmlFor`; the raw inputs `LoanCalculator.tsx:52-57`, `SalarySlipForm.tsx:93-96` and `SanctionModule.tsx:66-69` each have `<label htmlFor>`). Field errors are linked with `aria-describedby`.
  - **Non-text content:** the slip `<img alt="Salary slip">`, and the `<iframe title="Salary slip (PDF)">`.
  - **Dialogs:** native `<dialog>` with `showModal()` (focus trap, Escape) and `aria-labelledby`.
  - **Sliders:** `aria-valuetext` (`LoanCalculator.tsx`) plus a debounced `aria-live="polite"` total.
  - **Live regions:** `role="alert"` on errors (Alert, ErrorState, BreFailureList, ErrorFallback), `role="status"` on the waking banner and spinners, and sonner toasts.
  - **Navigation and structure:** `aria-current` on nav links, `aria-expanded` on Menu; one `<h1>` per page (PageHeader).
  - **Contrast:** every text, button and badge pair passes AA (`docs/UI.md` contrast table: badges 6.78–8.15:1, primary 6.70:1, secondary text 4.55–4.76:1).
