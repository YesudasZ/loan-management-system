# Deployment guide

Three services, all on free tiers:

| Piece    | Service                                      | Region                           |
| -------- | -------------------------------------------- | -------------------------------- |
| Database | MongoDB Atlas M0                             | AWS Singapore (`ap-southeast-1`) |
| API      | Render web service (Blueprint `render.yaml`) | Singapore                        |
| Web app  | Vercel (added at checkpoint B)               | global                           |

Keep a private note of every secret you create (Atlas passwords, `JWT_SECRET`). Never commit them.

---

## Checkpoint A: Atlas + Render

### 1. MongoDB Atlas

1. Sign in at https://cloud.mongodb.com (create an account if needed).
2. **Create a project:** top-left project picker → **New Project** → name it `LMS` → **Create Project**.
3. **Create the cluster:** **Create** (or **Build a Cluster**) → choose **M0 / Free** → Provider **AWS** → Region **Singapore (ap-southeast-1)** → Name `lms-cluster` → **Create Deployment**. If a "Connect to lms-cluster" dialog opens, close it; the next steps create the user and network rules explicitly.
4. **Create two database users:** left menu **Security → Database Access → Add New Database User**:
   - Authentication: **Password**. Username `lms_prod_app`. Click **Autogenerate Secure Password**, then **Copy** and save it.
   - **Database User Privileges** → **Specific Privileges** → **Add Specific Privilege** → role `readWrite`, database `lms_prod` (leave collection empty).
   - **Add User**.
   - Repeat for username `lms_dev_app` with `readWrite` on database `lms_dev`. This one is for your laptop.
5. **Network access (your laptop):** **Security → Network Access → Add IP Address → Add Current IP Address → Confirm.** Render's addresses are added in step 2.4 below.
6. **Connection strings:** **Database → Clusters → Connect → Drivers** → Driver **Node.js** → copy the string. It looks like:
   `mongodb+srv://<db_username>:<db_password>@lms-cluster.abc123.mongodb.net/?retryWrites=true&w=majority&appName=lms-cluster`
   Make two versions by filling in the user, the password **and the database name before the `?`**:
   - dev: `mongodb+srv://lms_dev_app:<dev password>@lms-cluster.abc123.mongodb.net/lms_dev?retryWrites=true&w=majority&appName=lms-cluster`
   - prod: `mongodb+srv://lms_prod_app:<prod password>@lms-cluster.abc123.mongodb.net/lms_prod?retryWrites=true&w=majority&appName=lms-cluster`

   If a password contains `@ : / ? # [ ]` or `%`, URL-encode it. Atlas's autogenerated passwords are alphanumeric, so this usually isn't needed.

### 2. Local backend against Atlas (sanity check)

1. Generate a secret for local use: run `openssl rand -base64 48` and copy the output.
2. `cp backend/.env.example backend/.env`, then set `MONGODB_URI` to the **dev** string and `JWT_SECRET` to the value from step 1.
3. From `backend/`: `npm run seed` (creates the 6 role accounts), then `npm run dev`.
4. `curl http://localhost:4000/health` should return `{"success":true,"data":{"status":"ok","database":"connected"}}`.

### 3. Render

1. Sign in at https://dashboard.render.com with **GitHub**. When GitHub asks which repositories Render may access, choose **Only select repositories** → `YesudasZ/loan-management-system`.
2. **New → Blueprint** → pick `loan-management-system` → branch `main`. Render reads `render.yaml` and shows one web service, `lms-api` (Free, Singapore).
3. Render asks for the variables marked `sync: false`:
   - `MONGODB_URI`: the **prod** connection string from step 1.6.
   - `JWT_SECRET`: a **new** value from `openssl rand -base64 48` (don't reuse the dev one). Save it; Vercel needs the same value at checkpoint B.
   - `CORS_ORIGINS`: `http://localhost:3000` for now. The Vercel URL is added at checkpoint B.
   - `TRUST_PROXY_HOPS`: `1` for now. It is measured and corrected at checkpoint B.

   Click **Apply** (or **Deploy Blueprint**). The first deploy will probably fail its health check, because Atlas doesn't allow Render's IPs yet. That's expected.

4. **Allow Render in Atlas:** in Render open **lms-api** → **Connect** (top right) → **Outbound** tab → copy each IP range listed. In Atlas → **Network Access → Add IP Address** → paste one range per entry, comment `Render Singapore` → **Confirm**.
   - If Render shows no outbound ranges for your instance, add `0.0.0.0/0` instead (comment `Render (free tier, no static IPs)`). The database is still protected by its password and TLS. This is recorded as a known limitation.
5. Back in Render: **lms-api → Manual Deploy → Deploy latest commit**. Wait for **Live**.
6. Check it: `curl https://<your-service>.onrender.com/health` (the URL is shown at the top of the service page). The first request after idling can take about a minute (free-tier cold start).

### 4. Seed production (from your laptop)

Render's free tier has no shell, so the seed runs from your machine against the prod database (your IP is already allowed in Atlas):

```bash
cd backend && MONGODB_URI='<prod connection string>' NODE_ENV=production npm run seed -- --force
```

Then confirm a login works on Render:

```bash
curl -s -H 'Content-Type: application/json' -d '{"email":"admin@lms.dev","password":"Password@123"}' https://<your-service>.onrender.com/api/v1/auth/login
```

**Send me:** the Render service URL, and whether you used the outbound ranges or `0.0.0.0/0`.
